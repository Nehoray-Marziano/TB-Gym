## Findings and changes

1. **Incorrect live occupancy totals — fixed and verified.** Before migration 22, members saw only their own RLS-visible bookings in the class-count view, so full classes reported zero or one booking. Database capacity enforcement still rejected overbooking and preserved tickets. Migration `22_public_occupancy_private_bookings.sql` replaces the join with a narrowly scoped security-definer aggregate in an unexposed schema, while retaining security-invoker session access and private booking rows. The actual SQL passes isolated PostgreSQL/RLS tests. The user applied it through the SQL editor; all twelve live capacity waves now show correct totals and preserve attendee privacy. Anonymous aggregates also match stable service observations across 64 existing classes, including 23 occupied classes, and direct REST access to the internal schema is rejected.
2. **Eight-digit email codes were rejected by the new six-digit UI guard.** The hardening pass introduced this regression. The configured Auth project generates eight digits; the existing input already allowed eight. Validation now accepts six to eight ASCII digits and gives explicit invalid-code feedback. Actual signup, wrong-code recovery, onboarding and returning login pass against real Auth.
3. **Installation encouragement could cover onboarding after opening during login.** Excluding onboarding from new timers did not hide an already-open prompt. Rendering now also requires an eligible route and authenticated identity. The production browser check passes with installation prompts enabled.

Test harness corrections are kept separate from application defects: the first server lacked network access to Supabase; fixture titles exceeded the UI's 30-character limit; native clicks needed settled scrolling, centering around sticky headers and hit testing; the booking fixture needed verified hydration, a unique route, the shared browser harness and the actual trainee shell; a subscription-read RPC was misclassified as a mutation; and a test storage preload ran on opaque `about:blank` pages. The member balance observer now reads persisted tickets through a separate service client instead of sharing the browser's refresh token. Original failed reports remain available under ignored `scratch/`.
